# Assumptions Log

Record every assumption that affects the rack design. Update this file whenever a mission changes a constraint.

| ID | Assumption | Type | Source / reason | Confidence | Affected decisions | Status |
|---|---|---|---|---|---|---|
| A-001 |  | facility / hardware / workload / budget / operations |  | low / medium / high |  | active / replaced / validated |

## Rules
- Vendor specifications are facts only when cited.
- Fictional scenario constraints should be labeled scenario inputs.
- Estimates should state their method and uncertainty.
- When a new mission invalidates an assumption, preserve the old entry and mark it replaced instead of rewriting history.
- Final recommendations should point back to the assumptions that drive them.
